## Frozen method

E28 keeps the E13-B v037 family-max reliability router, packaged CatBoost router, checkpoint weights and independent prediction behavior. The score matrix uses the existing family-max reliability score for labels supported by checkpoints; unsupported labels receive finite low fallback scores. Family-balanced probabilities preserve the original deterministic tie-breaking and are used for assignment fallback. The exact independent route was checked against the saved E13-B out-of-fold predictions: **0 mismatches across 2,699 rows**.

The fixed Kaggle deployment roster has 15 checkpoints: N0110, N0054, N0008, N0127, N0082, N0065, N0124, N0117, N0133, N0097, N0120, N0033, N0059, N0113 and N0071. Local parity uses E13-B's original five prompt-group out-of-fold router fits, each with its historical 15-member fold roster (37 unique checkpoint IDs across folds); the local OOF score is therefore reported separately from the fixed deployment roster.

## Kaggle package and run

The packaging script creates an isolated E28 kernel and dataset; the known-good E13-B v037 notebook and assets remain untouched. The kernel requires two visible T4 GPUs and fails if fewer than two are available. It starts two checkpoint workers behind a ready barrier, assigns `CUDA_VISIBLE_DEVICES=0/1`, writes checkpoint probability files atomically, and records per-checkpoint times, GPU assignment, memory and overlap. Grouping begins after both checkpoint workers finish. The initial kernel version failed because the old runtime package shadowed the new module; the import path was corrected and version 2 was queued.

The package currently generates E28-B and E28-C submissions with the original test ID order. E28-D is not included: local cached grouping time is short, but its prompt reconstruction runtime on Kaggle has not been benchmarked and must fit the nine-hour budget with margin first. No E28 submission has yet been recorded. ### Interpretation and evaluation caveat

This replay reproduces the *deployed* E13-B model: its CatBoost router was trained on out-of-fold correctness records from all V0 prompts, and its packaged per-checkpoint reliability statistics also use V0 labels. Therefore the 65.3870% fixed-roster baseline and grouped V0 scores are **in-sample development diagnostics**, not leakage-free estimates of generalization. The earlier E28 fold-held-out baseline (64.6465%) remains the appropriate cross-fitted local reference. The exact fixed roster is still important for deployment realism; the fixed-roster score should not be compared to the OOF score as if only the roster changed, because the router and reliability-statistics fitting protocols differ too.

E28-E does not change the E13-B model or its 0.606 Kaggle public baseline. The fixed-roster artifacts are saved under `artifacts/analysis/e28_fixed_roster/`; `scripts/run_e28_fixed_roster.py` reproduces the replay using the packaged router at `e13_b_router.cbm`, the existing V0 checkpoint probability caches, frozen E27 groupers and saved scenario row IDs. The fixed-roster results are registered separately as E28-E in `configs/ensemble_catalog_v2.json`.
