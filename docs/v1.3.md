# V1.3 Data Card

## Summary

V1.3 is a training-only collection of responses from two newly downloaded external corpora. It contains **only those corpora**; no V0, V1, or V1-all rows were appended. The build normalizes each source to the NLM response-classification schema and adds source provenance. `v1.3_clean` applies explicit defect rules; `v1.3_compact` additionally removes verified same-label near-duplicates.

| Artifact | Rows | Purpose |
|---|---:|---|
| [`dataset_v1.3.parquet`](../data/processed/dataset_v1.3.parquet) | 101,359 | Normalized source rows before clean/compact filtering |
| [`dataset_v1.3_clean.parquet`](../data/processed/dataset_v1.3_clean.parquet) | 92,096 | Recommended starting point for training experiments |
| [`dataset_v1.3_compact.parquet`](../data/processed/dataset_v1.3_compact.parquet) | 92,093 | Clean set with three additional verified near-duplicate rows removed |

The dataset has **three of the task's 18 model labels**. It is not a standalone replacement for the existing multi-class training data.

The GPT source rows are split across the recorded source datasets `greghavens/gpt-5.6-sol-coding-and-debugging-traces` (14,467) and `empero-ai/gpt-5.6-luna-sft-900x` (886). Source-reported model identity is retained as provenance; it was not independently verified. Preserve source attribution and review the original terms before redistributing or publishing a mixed dataset. The two inputs have separate licenses, so V1.3 is a mixed-license collection.

The GLM input uses the four primary harvest files. Overlapping register/thinking exports were not added as additional rows. The GPT input is `data/train.parquet`; its final user message and final assistant text are used for the prompt and response. A structured tool-call payload without assistant text is treated as an empty response and removed by clean.

Clean is intentionally defect-focused, not class balancing. The large GLM majority and small Luna class are properties of the source collection. Mixing V1.3 into an 18-class training set without sampling or loss weighting would add examples to only three classes and make GLM disproportionately represented within the added data.

## Data construction and fields

Each response is one labeled row. The common training fields are:

- `id`: deterministic V1.3 row ID derived from source identity and row position/ID.
- `text`: extracted assistant response.
- `model`: target NLM class label.
- `prompt_canon`, `prompt_id`: extracted prompt and its normalized grouping ID; use these groups when creating internal train/validation splits.
- `source_dataset`, `source_corpus`, `source_file`, `source_row_id`, `source_license`, `source_model_attribution`: source and attribution provenance.
- `provider`, `model_version`, `language`: normalized metadata.
- Additional source fields are retained where available, including GLM `register`, `thinking`, `source_tokens`, round/origin/mode, finish/truncation/cap flags, and GPT source dataset/config/split, trace, category/domain/task, and reasoning effort.

Missing metadata means unavailable or not applicable, not a negative value. For example, the GLM provenance table only covers some harvest rounds. The `source_tokens` field is source-reported for GLM and absent for GPT; it should not be treated as a common tokenizer count. GPT's repository describes the corpus as English; GLM carries `language` metadata for English and Chinese. The clean and compact sets retain **1,709 GLM rows marked `zh`**. No English-only filter was applied.

The GPT source's `lang` tags describe programming languages/task categories, not natural-language detection. They are retained through source metadata rather than interpreted as the response language.

## Cleaning and compaction

The clean pass removed **9,263 rows** from raw V1.3:

| Rule | Removed |
|---|---:|
| Missing or empty required field (primarily empty final assistant text in GPT-Sol traces) | 8,313 |
| Explicit source truncation/length-cap metadata | 912 |
| Normalized duplicate response | 18 |
| Serialized role/object/tool-log artifact | 14 |
| Explicit response truncation/failure marker | 6 |
| Other configured defect rules | 0 |

Counts are the factory's removal attribution; rows are assigned to the first applicable clean rule, so rule counts should not be interpreted as independent overlapping defect counts. The full row-level audit is [`v1.3_clean_removals.csv`](../data/processed/v1.3_clean_removals.csv).

Compact starts from clean and removes three rows whose same-label pairs pass both exact similarity checks: character 5-gram Jaccard **≥0.92** and word 3-gram Jaccard **≥0.85**. MinHash is an approximate candidate retrieval method, so the three verified removals do not prove that all near-duplicates were found. See [`v1.3_compact_removals.csv`](../data/processed/v1.3_compact_removals.csv) and the [clean/compact analysis](v1_3_clean_compact.md).

The clean corpus has 42,879 prompt groups. Many prompts have multiple responses: the factory diagnostic reports 39,598 same-label prompt groups with multiple rows (88,815 rows). Do not split rows randomly across training and validation; split by `prompt_id` to avoid prompt leakage.

## Response profile and known limitations

- In clean, response length is 6,190 characters and 858 whitespace-tokenized words at the median; the P10–P90 ranges are 1,098–18,136 characters and 174–3,068 words.
- The longest retained response is 841,540 characters. Define and record a model-specific context/truncation policy before training; this card does not mark long responses as defective.
- Clean responses are often structured: 78.9% match the report's Markdown/structured-format heuristic and 37.1% contain a code fence. These are regex diagnostics, not human quality ratings.
- The sources differ in prompt/task mix and attribution method. GLM includes multiple registers and 1,709 Chinese-tagged responses; GPT-Sol is heavily coding/task-trace oriented; GPT-Luna contributes only 886 rows. A classifier may learn source or task signatures correlated with a label.
- Source quality is uneven. In particular, 8,313 GPT-Sol traces have no final assistant text and were removed. Explicit truncation metadata is only available for part of the GLM corpus. Unmarked incomplete responses may remain.
- No accuracy, generalization, or training benefit has been established for V1.3 by this card. The validation checks below establish data isolation only.

## Validation and overlap

V1.3 is training data only. The build and clean/compact passes checked it against the frozen V0 validation set (540 rows; split SHA-256 `147ce64eb0f54e5536807603701d11f373834e72f627262fb4c9436dd380bcab`); the resulting datasets have zero V0 validation ID or prompt overlap. This is not a V1.3 train/validation split: create any diagnostic split by `prompt_id` and keep the frozen V0 validation set unchanged for project comparisons.

The separate raw-source comparison in [`external_candidates_quality.md`](external_candidates_quality.md) found zero normalized response overlap and zero prompt overlap with V1-all for these input corpora. That comparison is useful when considering a mixture, but deduplicate again after any further transformation or combination. V1.3 itself was not constructed by appending to V1-all.

## Suggested use in further training

Treat `v1.3_clean` as the default supplemental candidate and `v1.3_compact` as a near-duplicate sensitivity variant. The compact version differs by only three rows, so it is unlikely to change the overall class balance materially. Keep the raw version for traceability and alternative curation experiments, not as the default training input because it contains known empty, truncated, and duplicate rows.

For a controlled V1-all mixture experiment:

1. Keep V1-all as the baseline and use the same model, tokenizer, train/validation protocol, and frozen V0 validation set for every condition.
2. Compare baseline V1-all against V1-all + `v1.3_clean`; optionally repeat with `v1.3_compact` to measure sensitivity to the three compact removals.
3. Add a sampling/weighting condition. Cap or sample GLM additions and select GPT-Sol/Luna rows by source and prompt group; alternatively use class-weighted loss. Do not assume the raw V1.3 class proportions are desirable for the 18-class task.
4. Report overall accuracy and macro/balanced accuracy, plus per-class precision/recall for the three added labels and all existing classes. Check whether gains are confined to coding-heavy examples or come at the expense of other labels.
5. Save the exact row IDs, source hashes, sampling seed, and class/source counts for each mixture so the run can be reproduced.

An initial experiment should not discard the Luna class simply because it is small. Treat it as a low-support class: report its uncertainty and compare retaining all 886 clean rows with any sampling or weighting alternative. Avoid using V0 validation performance to tune row selection repeatedly; reserve a prompt-grouped V1.3 development split for selection and use V0 for the established project comparison.
