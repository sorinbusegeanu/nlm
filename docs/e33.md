## Outcome

E33-F is best in all four columns: it improves on E31 by **+3.3649 pp** independently, **+3.5681 pp** with E19-F-A, **+3.4002 pp** with E19-F-C, and **+3.5502 pp** with E19-D. E33-A, D and E regress; E33-B is near baseline; E33-C learned no qualifying conditional rules and reproduces baseline.

These are V0-reused scenario results, so the E33-F gain is a candidate for external validation, not a deployment claim. The E31 router itself remains frozen and V0-exposed.

## Evaluation notes

All seven rows use the same fixed E31 40-checkpoint roster, V0 rows, 50 scenario memberships and cached E19-F-A/E19-F-C/E19-D reconstructed groups. The baseline is reproduced from E31's cached 40-checkpoint scores and scenario predictions before reporting variants.

The 50 scenarios reuse V0 responses; treat the values as a correlated robustness comparison, not independent validation. Rules use prompt-group cross-fitting. E33-F trains its candidate-error classifier on inner prompt-group OOF reliability features, then scores each outer held fold. E31's frozen base score matrix is unchanged.

Hard candidate exclusions retain the original E31 scores if every candidate is removed. For Hungarian assignment, excluded labels are restored in descending original E31 score order only until a complete unique-label matching becomes feasible. D and E apply multiplicative reliability factors before independent decoding or assignment. E33-F multiplies E31 scores by the predicted candidate-correctness probability.

E33-A/B rule thresholds: support ≥30, wrong rate ≥97%, and precision below the training-fold class prior. E33-C conditions support/wrong rate on E31 selecting that candidate (≥20 and ≥95%). E33-D uses empirical precision/prior ratios for supported negative rules. E33-E uses a prior-shrunk precision estimate (prior strength 30). E33-F uses CatBoost with 400 iterations, depth 6, learning rate 0.05, balanced class weights, and 8 CPU threads.

Artifacts: `artifacts/analysis/e33/metrics.json`, `fold_rule_statistics.parquet`, `fold_rule_counts.csv`, `oof_adjusted_scores.npz`, `scenario_predictions.parquet`, and the five `e33_f_fold*.cbm` models.

### Local E19-D throughput benchmark

A corrected benchmark used 32 of the longest official V0 response texts, the pinned Qwen3.5-4B snapshot, deterministic generation, and `max_new_tokens=1024`. Results include generation only (not model loading):

| Batch size | Seconds for 32 rows | Rows/second | Peak allocated VRAM |
|---:|---:|---:|---:|
| 2 | 130.80 | 0.245 | 8.76 GiB |
| 4 | 80.97 | 0.395 | 9.02 GiB |
| 8 | 46.60 | 0.687 | 9.56 GiB |
| 16 | 25.08 | 1.276 | 10.64 GiB |

The calibrated E19-D Qwen3.5-4B maximum is 32 on the local RTX 5070 Ti. The prepared runnable package reads this value from the saved calibration artifact and halves the batch on OOM. Kaggle version 1 used batch 2; version 2 reads the calibrated batch 32. The exploratory batch-8 projection was about 1.62 hours locally for 4,000 rows. The exact batch-32 calibration took 61.13 seconds for 64 longest V0 inputs, or about 1.06 hours by linear extrapolation to 4,000 rows, excluding model loading and embedding/grouping. These are local estimates, not Kaggle runtime measurements; hidden test lengths and T4 throughput may differ. An earlier estimate based on `data/raw/test.csv` was invalid because that local file is a 3-row debug sample and has been discarded.


The exact-model calibration in `artifacts/analysis/e33/e33_qwen4b_batch_calibration.json` tested the 64 longest V0 texts with the E19-D prompt, 12,288-token input cap, and 1,024 generated-token cap. Batch 64 OOMed; batch 32 completed all 64 rows in 61.13 seconds with 14.83 GiB peak allocated VRAM. E33's runtime reads batch 32 from this artifact and halves on OOM, accommodating the slightly smaller Kaggle T4 memory. The prior E20-D Qwen batch-64 calibration is for Qwen3.5-2B and is not used for E19-D's 4B model.
